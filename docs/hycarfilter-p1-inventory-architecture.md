## 2. 四仓架构设计

> 四仓定位：**hycarfilter 主站负责「说服采购者」**，三个 MkDocs 子站负责「被检索、被机器读、被引用」，主站与子站**内容零重复**，子站是主站的基础数据支撑。

```
hycarfilter.com        (Astro 商业主站)   —— 面向采购者决策的营销站
data.hycarfilter.com   (MkDocs 产品数据库) —— 全产品结构化规格，机器可读为纲
tech.hycarfilter.com   (MkDocs 技术/检测)  —— 生产技术/参数/检测/QC/行业标准
market.hycarfilter.com (MkDocs 行业报告)   —— 全球市场/区域需求/趋势/出口情报
```

### 2.1 hycarfilter（Astro 主站）— 商业主站信息架构

| 导航 | 路由（建议） | 页面类型 | 源内容 → 内容深化策略 |
|---|---|---|---|
| 首页 | `/` | 聚合门户 | 源 7 品类轮播 → **价值主张（"清河滤清器之乡·出口型工厂"）+ 7 品类入口 + 核心优势数字 + 询盘 CTA** |

**每页类型的「内容深化」统一扩展点**（采购者决策视角，原创主观观点段必含）：
1. **采购需求挖掘**——OE/OEM 号对照、适配车型表、材质与寿命、包装规格（内盒/外箱/托盘）、MOQ、交期、认证（IATF 16949 / ISO 9001 / EAC / GCC 等出口认证）。
2. **选型指南**——按工况（粉尘/高寒/高温/长里程）、按发动机类型、按地区油品/路况。
3. **主观观点段**——研究员署名观点（例：俄区冬季首选高回弹密封圈机滤；中东多沙尘首选纳米空滤），明确与市场/技术子站互链。

### 2.2 data.hycarfilter（MkDocs）— 产品数据库核心

**定位**：全产品结构化规格的**唯一事实源（canonical）**，机器可读为纲（每品类一份 CSV/JSON + 渲染表格 + 型号索引 + 交叉引用表）。**不与主站营销文案重复**（主站引用其数据、不复制其表）。

**字段 schema 草案（每型号一行）**：

| 字段组 | 字段 |
|---|---|
| 标识 | `model`(型号) / `brand`(hycarfilter) / `category`(品类) / `sku` |
| 尺寸 | `outer_diameter` / `inner_diameter` / `height` / `thread`(螺纹) / `gasket`(密封) |
| 性能 | `filtration_efficiency`(过滤效率%) / `nominal_rating`(微米级) / `media`(滤材) / `bypass_valve_psi`(旁通阀) / `flow_rate` |
| 适配 | `applicable_vehicles`(适用车型) / `oe_numbers`(OE 对照号) / `cross_reference`(竞品对照) |
| 材质 | `housing_material`(壳体) / `media_material`(滤纸) / `endcap`(端盖) / `seal`(密封圈) |
| 包装 | `packing_inner` / `packing_outer` / `carton_qty` / `pallet_qty` / `net_weight` |
| 出口 | `moq` / `lead_time` / `certifications` / `target_markets` / `hs_code` |

**结构**：
- `models/*.json`（canonical 单值表，所有仓引用同一文件）
- `index/` 型号索引（按品类 / 按车型 / 按 OE 号三种倒排）
- `crossref/` 交叉引用表（车型 ↔ 型号 ↔ OE ↔ 竞品件号）
- `docs/` MkDocs 渲染（表格 + 下载 CSV）

### 2.5 数据一致性机制（核心约束）

1. **Canonical Dataset（单一值表）**：所有「型号/参数/规格」的**唯一真值**存于 `data.hycarfilter` 的 `models/*.json`。主站 Astro 在构建期读取该 JSON 渲染产品页；tech/market 站引用同一 JSON 做交叉引用。**任何值只在一处定义，改一处全站生效**——满足「同值跨站唯一」。
2. **命名规则**：品牌统一 `hycarfilter`（废弃源站残留 `Kervis` / `Hongying`）；型号前缀 `HF-` + 品类代码（`AF`空气滤 / `CF`空调滤 / `OF`机滤 / `FF`燃油滤 / `TF`变速箱滤网 / `WB`雨刮 / `LED`）+ 3 位序列，如 `HF-AF-001`。
3. **跨站链接结构**：主站产品页 → data 型号详情（规格唯一源）→ tech 对应工艺/检测页（"这款滤纸怎么做/怎么测"）→ market 相关区域报告（"这款在中东怎么卖"）；反向：子站每页顶部面包屑回链主站对应产品/询盘。形成**主站→data→tech→market 的 4 层互链闭环**。
4. **内容去重红线**：主站只写「营销文案 + 采购决策 + 主观观点」，子站只写「结构化数据 / 技术原理 / 行业数据」；同一事实**绝不两边成段复述**，只做引用。
